# 窗口插帧助手 · WindowInterp 1.6.1

默认使用苹果 VideoToolbox 的 `VTLowLatencyFrameInterpolation` 做 **2× / 4× 插帧**，每对参考帧生成一张或三张中间帧。选择一个窗口，输出覆盖层跟随它的位置和大小，鼠标与键盘操作穿透到原应用。

**苹果原生模式：Apple Silicon，macOS 26 或更新系统，且运行时处理器报告支持。** 旧的 LSFG 诊断路径仍可在 macOS 15+ 使用。

[下载 v1.6.1 苹果原生版](https://github.com/lrylnx/WindowInterp/releases/tag/v1.6.1) · [版本记录](CHANGELOG.md)

## 使用

1. 双击本目录的 `窗口插帧助手.app`，授予屏幕录制权限，按系统提示重新打开。
2. 选择源窗口，抓取方式默认「窗口」，点击「开始插帧」。可选择原生 2× 或 4×；外接高刷屏可选 4×。
3. 看视频时默认选择「内容节奏 → 自动视频」，不需要先知道原视频帧率；积累连续画面变化后，自动估算常见24 / 25 / 30fps。例如识别到25fps后，4×目标约100fps。也可手动覆盖。此模式提高采集上限、确认整帧重复后跳过插值、恢复均匀时间轴，并优先高分辨率级联插帧。静止或重复画面的呈现计数会降低。
4. 通用窗口模式下，已知视频为 30fps 时，可将「采集上限」设为 30fps，4× 的目标约 120fps；「自动」按屏幕与倍率决定窗口捕获上限。这里并不检测视频解码帧率。
5. `⌃⌥P` 暂停 / 继续，`⌃⌥S` 停止。关闭控制窗口后可从 Dock 或菜单栏重新打开。

保留窗口跟随、整屏采集、鼠标穿透、CAS 锐化、锐化强度热更新、右上角角标及 Metal HUD。原生模式不使用 LSFG 的「性能模式」，界面显示「苹果原生插帧」。

v1.5.1 修正原帧与中间帧交替时的几何抖动：插帧工作尺寸按 16 对齐后，以宽高两个方向分别还原到原始画布，避免等比居中放大产生边缘位置变化。

v1.5.2 默认按完整 Retina backing 像素采集和输出，取消旧的面板像素封顶，避免缩小后又由系统放大导致文字变软。苹果中间帧新增静态细节保护：参考帧一致且插帧图像低频内容一致的区域使用高清原帧；运动边界扩大保护，快速物体扫过的区域另行检查，保留插帧结果。此功能是保守的图像变化判断，不能保证所有运动都识别正确。它增加 GPU 合成和内存带宽开销；苹果光流工作预算仍保持约 720p。可用 `--limit-capture-pixels` 恢复旧的面板封顶诊断路径。

v1.5.3 新增苹果原生 4×，保留 Retina 原帧、静态细节保护和几何对齐。4× 会增加处理负担，不能保证所有尺寸和内容都跑满高刷屏。

v1.5.4 修正细节保护的时间参考：每个中间帧使用相应相位的前后原帧混合，避免缓慢变化的阴影提前跳到后一帧亮度。新增采集上限和窗口采集 / 呈现帧率区分。浏览器窗口更新可能包含重复的视频画面、页面动画和控件更新；窗口采集帧率及呈现 FPS 均不代表视频的不同解码帧数量。

## 视频模式

「自动视频」比较画面中间6个区域的变化时间，多个区域持续支持同一节奏后，自动应用约24 / 25 / 30fps。识别期间先显示捕获原帧；静止时保留已识别结果，持续运动不再支持原节奏时重新判断。浏览器视频也可使用，无需读取网站或安装扩展。这是画面节奏估计，不是视频解码元数据检测；只覆盖常见24 / 25 / 30fps近似节奏，暂不区分23.976与24、29.97与30。50/60fps、变帧率、很小的视频区域、低运动或复杂页面可能无法可靠识别，未锁定时显示原帧。手动视频模式和通用模式仍可选择。页面动画、丢失的源画面会影响恢复效果。模式切换、倍率与采集参数可在后台应用。

- 提高捕获上限至60fps以观察源画面的变化。先稀疏比较快速排除不同帧，再逐行比较全部BGRA像素确认重复，避免漏掉小物体和细微阴影变化；不凭小缩略图就跳帧。
- 按指定帧率恢复时间轴，去掉采样相位抖动；静止段保留静止，新变化过快时限制时间轴领先，尺寸变化/跳转/过期时间线重置。
- 4×使用播放器相同的三级联1/2相位请求。macOS27+优先保持捕获尺寸，工作预算最多约1080p；macOS26保留720p兼容预算。配置或实际处理失败时明确记录兼容回退。
- 视频原帧与中间帧采用相同YUV转换/缩放路径，绕过通用模式的UI静态细节混合；约140ms显示排程缓冲，为全尺寸插帧及渲染留出余量。声音仍由原播放器播放，可能有音画延迟。
- 窗口先被原应用缩小时，其丢失的原视频细节无法保证恢复。放大原视频窗口有助于保留捕获细节。高分辨率比原720p模式增加负载。

自动识别与页面动画干扰检查见 [自动节奏验证](dev/自动视频节奏验证-2026-10-24.md)。

本机1920×800、25fps实际视频测试：运动段呈现中位约100fps，确有重复画面被跳过；不是所有内容稳定100fps或已经完全等同直接解码播放器的保证。详见 [视频模式验证](dev/视频模式验证-2026-10-24.md)。

## 通用模式插帧和画质

- 每对捕获帧只调用一次苹果低延迟处理器：2× 生成相位 0.5，4× 生成相位 0.25 / 0.5 / 0.75。所有中间帧均由处理器生成，按源时间戳排程。
- 采集上限为 `min(60, 目标刷新率 / 倍率)`：60Hz 屏最多采集 30fps 并生成约 60fps；120Hz 屏最多采集 60fps 并生成约 120fps，4× 在 144Hz 屏最多采集 36fps 并生成约 144fps，30fps 内容理论输出 120fps。实际结果取决于源窗口、捕获时序及处理能力；120fps 在 144Hz 下仍有刷新节奏差异。高帧率源在 60Hz 屏也会被采样到最多 30fps；此模式适合低帧率内容，原本稳定 60fps 的内容未必获益。
- 捕获及原帧保留窗口原分辨率。插帧工作预算最多 921,600 像素，宽高向下按 16 对齐，例如 1920×1080 在 1280×720 上插帧。中间帧由显示端缩放回窗口大小，可能比原帧软；这是本版的性能选择，不是苹果硬件的统一上限。日志会记录实际工作尺寸。
- 独立复制捕获帧，及时归还 ScreenCaptureKit 的 IOSurface，避免播放缓冲拖慢采集。输入邮箱和待显示帧均设上限，超时帧会丢弃，停止 / 暂停后取消待显示帧并释放处理会话。
- 播放采用固定延迟，通常含至少 75ms 的排程缓冲；启动时的模型预热不会变成永久的深队列。此值不是端到端延迟实测。
- 状态中的呈现帧率使用 Metal 提交或 drawable 实际显示回调统计；原生输出 FPS 和中间帧计数使用实际显示回调，不能等同显示器独立逐帧光学测量。
- 苹果插帧失败会明确停止并提示，不静默退回原帧继续显示倍率。静态窗口可以显示原帧，没有连续运动时无需凭空产生中间帧。

苹果官方把此接口描述为针对 Apple Silicon 优化的机器学习视频处理。没有在代码中强制指定 ANE，也没有据 CPU 占用推断整机功耗。

## 限制

原应用继续播放声音，因此插帧延迟可能造成音画不同步。窗口跨 Space 或停止渲染时可能无法继续采集。不支持 DRM 保护画面；目前输出 SDR / 8-bit。首次启动、恢复和尺寸变化需要重新准备处理器，不能保证完全无停顿。

## 构建与验证

```sh
zsh build.sh
# 只构建苹果原生版，跳过可选 LSFG 资源：
WI_NATIVE_ONLY=1 WI_SYNC_DESKTOP=0 WI_BUILD_APP="$PWD/dist/native/窗口插帧助手.app" zsh build.sh
zsh dev/verify-local.sh       # 进程生命周期及实际 CAS 着色器
zsh dev/verify-apple.sh       # 真正调用苹果插帧、像素差异、尺寸变化和停止
xcrun swiftc -O dev/testpattern.swift -o dev/testpattern
python3 dev/verify-apple-live.py  # 需要屏幕录制权限，会短暂打开测试窗口
WI_TEST_MULTIPLIER=4 WI_TEST_TARGET_FPS=144 python3 dev/verify-apple-live.py # 外接144Hz屏验证
WI_TEST_MULTIPLIER=4 WI_TEST_TARGET_FPS=144 WI_TEST_CAPTURE_FPS=30 python3 dev/verify-apple-live.py # 30fps采集上限
```

使用运行时 Objective-C 桥接公开 VideoToolbox API，允许本机旧 SDK 编译；运行时仍要求系统提供苹果低延迟接口。没有复制苹果框架，也没有使用私有插帧 API。默认苹果模式无需第三方 LSFG 引擎文件。GitHub 的 v1.6.1 下载包只包含苹果原生版；macOS 15 用户可使用 [v1.4.2 历史版本](https://github.com/lrylnx/WindowInterp/releases/tag/v1.4.2)。

可用 `WI_BUILD_APP=/绝对路径/窗口插帧助手.app WI_SYNC_DESKTOP=0 zsh build.sh` 构建独立验证副本。构建优先使用本机固定签名身份，避免无谓更换屏幕录制授权身份。

旧 LSFG 路线可用 `窗口插帧助手.app/Contents/MacOS/WindowInterp --backend lsfg` 启动，需要已有的本机引擎资源。历史版本说明、引擎来源和许可信息见 [LSFG 历史说明](docs/LSFG-legacy.md)。
