# WindowInterp 1.4.2 优化与验证

## 基线与环境

- 基线：`origin/main` / `94430830224586fb311caf8c7a4d758235209236`，版本 1.4.1。本轮 `git fetch origin` 后确认没有更新的主分支提交。
- 在接手时未提交的修改上继续修复并完成验证。应用版本 1.4.2，构建号 8。
- 本机：Apple M4、16 GB 内存、macOS 27.0.1（26A434）、内建 Retina 显示屏。
- 编译目标：`arm64-apple-macos15.0`；`vtool` 确认二进制 `minos 15.0`。本轮没有在 macOS 15 上运行。

## 完成的修改

1. **降低等待期间呈现旧帧的机会。** 采集端只保留最新画面；渲染端等 GPU 名额、取得 drawable 后再取最新帧。GPU 忙时不提前拿走旧帧，也不丢掉最后一帧后无人重新唤醒。等待放在独立渲染队列，drawable 暂不可用时避免空转。
2. **修复窗口回跳。** 位置跟随只查询目标窗口；5 秒兜底检查不再复用启动时缓存的坐标。目标关闭时停止会话并提示。恢复采集、预热替换引擎时重新读取 ScreenCaptureKit 的窗口尺寸和所在显示器。
3. **修复暂停竞争。** 重复继续不会重新启动采集；暂停会使未完成的异步恢复失效。控制进程给暂停请求附加递增版本，后台旧消息不能覆盖最新请求，新引擎接管时继承当前暂停状态及版本。
4. **避免控制窗被后台管道拖住。** 命令写入移到串行后台队列，关闭父进程多余的管道读端；引擎无响应时仍能处理界面操作并限时退出。
5. **画质与 GPU 容错。** 保持采集图像存活至 GPU 完成；CAS 编码失败时使用原始画面，避免呈现未写入的中间纹理。GPU 提交失败会提示并停止会话。
6. **易用性。** 锐化滑块显示百分比，说明建议从 20–40% 开始。保留原始画质默认项、手动刷新列表、固定光流精度 1.0 与采集上限 60fps，以及既有的角标和 Metal HUD。

## 验证结果

### 离线与构建

`zsh dev/verify-local.sh` 通过：

- 引擎消息分帧、环境变量隔离、JSON 往返与正常退出。
- 向不读取命令的引擎写入 512 KiB，控制线程发送操作在 0.5 秒内返回；卡死引擎按时被回收。
- 画质选项只包含原始画质和 CAS，没有恢复无效的放大选项。
- 从当前 `main.swift` 提取真实 CAS Metal shader 执行：零强度 MAE 为 `0.000`，非零强度产生锐化响应，中间纹理复用检查通过。

优化构建与 `codesign --verify --deep --strict` 通过，沿用本机固定签名身份。已检查实际控制窗，锐化百分比与各组控件没有截断。

### 真实 LSFG 动态验证

`python3 dev/verify-live-settings.py` 使用动态测试图及应用正常启动权限，验证：

- 实际生成插入帧；2× 场景日志出现约 30fps 输入与 60fps 输出。
- 2× / 3× / 4× / 12×、性能模式、窗口与整屏采集切换，控制进程持续存活。
- CAS 实时调节保持同一后台引擎。
- 暂停后帧数停止增加；继续后恢复。
- 重复继续、快速继续后暂停不会重建或意外恢复采集。
- 暂停时切换倍率，新引擎保持暂停；继续操作能恢复新引擎。检查控制进程与后台引擎的暂停版本，旧消息不会覆盖请求。
- 连续修改最终应用最后一项；只杀死预热中的新引擎时，原引擎仍继续输出。
- 停止、重新开始、退出后清理测试创建的后台进程。

测试结束恢复原有偏好。动态测试日志保存在已忽略的 `dev/verification-live-settings/`，不提交个人窗口信息。

### 真实窗口跟随

`dev/verify-overlay.swift` 创建自己的源窗口，暂停期间移动和缩放，再恢复，跨越多个 5 秒检查周期核对源窗口与覆盖层：

```text
PASS real overlay follow: samples=240, staleBounds=0, missing=0
```

最初的测试脚本用 Bundle ID 查找第二个应用实例，在本机没有找到诊断进程，曾误报缺少覆盖层。已改为从该次启动的独立输出读取 PID，再核对 WindowServer 中的真实窗口，不把“没有观察到进程”算作通过。

## 适用边界

这轮证据覆盖功能、状态竞争与窗口跟随，没有进行优化前后的端到端延迟、功耗或长时间压力 A/B 测量，不能据此宣称固定百分比的性能提升。CAS 测试只证明滤镜真实生效，不代表恢复了源视频丢失的细节。LSFG 算法及引擎二进制未更换，快速运动、遮挡、字幕与切镜头的插帧伪影仍需结合实际内容判断。
