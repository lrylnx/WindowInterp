## 0. 一句话结论

- **你已经在用这条路里最成熟的那个 mac 实现**：`namo-2938/lsfg-metal`（原 `itsOwen/lsfg-metal`）。
  它的**公开源码停在 v0.3.0**，而你本机二进制是 **v0.8.0** —— 你的引擎比公开源码还新，
  GitHub 上**没有比 v0.8.0 更新的公开版本**。
- **「小黄鸭内核」= LSFG 着色器包 `lsfg-vk.dll`**，来自 Steam 版 Lossless Scaling 的 **`lsfg-vk` 分支**。
  引擎最新是 **LSFG 3.1**（应用端已到 3.2.x，但没换引擎）。该分支最后更新 **2026-08-27**。
- **真正能同时降延迟 + 提画质 + 应用于游戏的，是「把 lsfg-metal 直接注入 CrossOver 容器」**
  —— 就是你在 B 站看到的「当补丁插进 crossover」那条路，也正是 lsfg-metal 的设计用途。
  它省掉你现在这条「屏幕采集 → 再插帧」的回路。

## 1. 先摸清家底：你现在的引擎到底是什么

| 事实 | 证据 |
| --- | --- |
| 引擎 shim = **lsfg-metal v0.8.0** | 引擎日志 `Loaded lsfg-metal layer version v0.8.0` |
| 公开源码版本 = **v0.3.0** | `namo-2938/lsfg-metal` 最后一次提交 `release: v0.3.0`（2026-09-18），无 Release 资产 |
| 你手上的 v0.8.0 来源 | `MetalFrame.app`（本机），其上游自述为 `github.com/itsOwen/lsfg-metal` |
| 着色器包 = `lsfg-vk.dll` | PE32+ x86-64，2,143,232 B，SHA256 `d22b2d3f77b31fb7926a08dec2a118c6e83ba6e772fe0f16476abf986c865804` |
| 扩展引擎 = `liblsfg_extended.dylib` | 由 `extend_engine.py` 把倍率上限 4→12 的二进制补丁版 |
| MoltenVK | `libMoltenVK.dylib` 10,925,552 B（上游 KhronosGroup/MoltenVK，要求 ≥1.4.2） |

**你现在的数据流**（这条路径决定了延迟与画质上限）：

```
源 App 窗口
  → ScreenCaptureKit 采集（8-bit RGBA8，SDR）
  → CIImage 绘制到 CAMetalLayer
  → present 时被 lsfg-metal 的 Metal present hook 拦住
  → LSFG 着色器（lsfg-vk.dll）生成中间帧
  → 真正出屏
```

关键：**采集这一环是 8-bit RGBA8**，是画质的天花板（10-bit / 浮点源也一样被压到 8-bit，
平滑渐变可能轻微 banding）；同时**采集+回灌本身要吃掉约一帧**，是延迟的主要来源之一。

## 3. 「有没有更新的内核版本」——分三层回答

| 层 | 是什么 | 现状 | 你能做什么 |
| --- | --- | --- | --- |
| **L1 着色器引擎** | LSFG（真正的「小黄鸭内核」），即 `lsfg-vk.dll` | ~~最新 LSFG 3.1~~ **已证伪**：工具内文件版本资源 = `FileVersion 3.2.2.0`，与最新零售同版本号 | ~~从 Steam `lsfg-vk` beta 分支重取~~ **无更新可换**。零售默认分支甚至不含 `lsfg-vk.dll`（只有 DXBC 的 `Lossless.dll`）；两者的 SPIR-V 逐字节零重合，是不同东西。若将来真有新内核，用 `dev/rebuild-lsfg-dll.py --minimal` 换 |
| **L2 mac 宿主 shim** | lsfg-metal（驱动着色器、做 pacing/present hook） | 公开 **v0.3.0**（2026-09-18）< 你的 **v0.8.0** | **你已经领先公开版**，没有可升级的公开版本。想再新只能等作者放构建，或自己从 0.3.0 源码编（= 倒退） |
| **L3 图形驱动** | MoltenVK | 需 ≥1.4.2（1.4.2 修了导入纹理驻留与 device loss） | 确认你的 `libMoltenVK.dylib` ≥1.4.2（你的路径其实走 Metal 前端，不直接依赖 MoltenVK，影响小） |

**结论**：GitHub 上**不存在比你更新的 mac 引擎**。唯一的「更新内核」动作是把 **L1 的
`lsfg-vk.dll` 换到最新版**（拿 3.1 的画质修复），而不是换 v0.3.0 的源码。

## 4. 优化清单（画质 / 帧率 / 延迟）

### 4.1 延迟

| 旋钮 | 你现状 | 建议 | 说明 |
| --- | --- | --- | --- |
| **架构：采集 → 插帧** | 有采集回路（+约一帧） | **改走 CrossOver 注入**（见第 5 节） | 收益最大：省掉采集与回灌，直接拦游戏自己的 present |
| pacing 模式 | `vsync`（fixed） | 试 **`adaptive`** | adaptive 把生成帧拟合到显示时隙，高刷屏上通常更稳、少堆一拍 |
| `LSFGM_OVERRIDE_PRESENT_MODE` | 默认 `true`（强制 vsync） | 试 `=0` | 让游戏自己掌握 present 模式，某些场景少一拍 |
| `LSFGM_LATENCY` | 未开 | **打开** | 引擎自带 p50/p95 延迟统计（每 120 次回调），比自己截图测量更省事 |
| 倍率 | 5×（144Hz） | 游戏用 **2×/3×** | 高倍率是结构性堆积，2× 在 144Hz 上净增仅约 7ms |

### 4.2 画质

| 旋钮 | 你现状 | 建议 |
| --- | --- | --- |
| `LSFGM_FLOW_SCALE` | **0.50**（为省电降的） | 画质优先时提到 **0.75–1.0**。代价：光流计算量随分辨率**平方**涨（0.5→1.0 约 4× 光流开销） |
| shader set | quality（`performance_mode=false`） | 保持。performance 模式画质略降（3.1 修过它的 bug，但仍是省电档） |
| 采集色深 | **8-bit RGBA8** | 这是天花板的来源。走 **CrossOver 注入**可直接吃游戏的 10-bit/float 交换链并在 Metal 前端用 `RGBA16Float`/`RGB10A2`，少 banding |
| 工作分辨率 | 采集尺寸封顶到面板物理像素 | 保持；别让采集分辨率超过屏幕物理像素（白烧 GPU） |

### 4.3 帧率

- 目标：`源帧率 × 倍率 ≈ 屏幕刷新率`。144Hz 主屏：24fps→6×（扩展引擎、延迟大，视频用）、
  30fps→4×、48/60fps→2×、满帧源**别开**。
- **源已满帧时插帧必然变差**（流畅度零收益 + 伪影全暴露 + 白加延迟）——这是规律，不是 bug。

## 5. 关键路线：把 lsfg-metal 当 CrossOver 补丁（B 站那条路）

**为什么值得做**：lsfg-metal 原本就是**给 Wine 游戏用的 shim**，直接注入游戏进程、
在游戏自己的交换链/present 上插帧。相比你现在的「外部采集」：

- **延迟更低**：没有「采集 → 回灌」那一环，也没有额外的合成；
- **画质更好**：直接吃游戏的帧缓冲格式（10-bit / HDR10 / RGBA16Float），不经过 8-bit 采集；
- **真正的「输入透明」**：游戏是前台，插帧层只碰画面，键鼠天然直达（正是小黄鸭的跟手原理）。

**接入方式**（lsfg-metal README 的官方做法）：

```sh
# Vulkan 路径（DXVK / vkd3d-proton / WineD3D Vulkan）
export DYLD_LIBRARY_PATH="$HOME/lsfg:$DYLD_LIBRARY_PATH"   # shim 冒充 libMoltenVK.dylib

# Metal 路径（DXMT / D3DMetal，CrossOver 26 默认用这俩）
export DYLD_INSERT_LIBRARIES="$HOME/lsfg/libMoltenVK.dylib"
export LSFGM_METAL=1

# 配置
export LSFGM_ENV=1
export LSFGM_MULTIPLIER=2
export LSFGM_FLOW_SCALE=1.0
export LSFGM_DLL_PATH="/path/to/lsfg-vk.dll"
```

**前置条件与你的现状**：

| 条件 | 你的现状 |
| --- | --- |
| x86_64 Wine 跑在 Rosetta 下 | ❌ **本机没装 CrossOver / Whisky**（需要先装） |
| 自备 `lsfg-vk.dll` | ✅ 已有（SHA256 `d22b2d3f…`） |
| macOS ≥ 11 | ✅ 15.8.1 |
| 目标游戏走 DXMT / D3DMetal / DXVK | 需在 CrossOver 容器高级设置里选 |
| 苹果原生插帧备选 | ❌ 你是 15.8.1，`VTLowLatencyFrameInterpolation` 需 26+，**用不了**；但 `VTFrameRateConversion`（15.4+）可用（你 `frameinterp` 已验） |
