# WindowInterp v1.3.0 优化与验证

日期：2026-10-15。当前环境：macOS 27.0.1，主屏 2560×1440 / 100Hz。历史记录中的 M4 / macOS 15 与本次环境不同，旧功耗、延迟数字不能直接当作本次结果。

## 修改设置为什么会重载

旧版把 LSFG 注入控制窗口进程，倍率、性能模式通过环境变量在启动时设置。UI 调用 `relaunch()`：停止输出、创建新应用进程、关闭原应用，造成控制窗口重开、选中状态丢失和画面中断。

新版使用同一已签名 App 中的两个进程角色：

- 控制进程维护窗口列表、设置、菜单与全局快捷键，不注入 LSFG，也不预先创建 Metal 设备。
- 后台引擎进程负责采集、LSFG、穿透覆盖层和悬浮控制；不创建控制窗口、Dock 项或重复注册快捷键。
- 倍率、性能模式、抓取方式变化时，合并 250ms 内的连续操作，预热替代引擎。它在原输出后方、低透明度下准备，待采集有画面且引擎日志出现 `generated > 0` 才交接，原输出继续保留。
- 新引擎启动失败、目标不存在、权限失败或等待超过 30 秒时保留原引擎，回退设置并显示原因。
- 画质、锐化、角标、Metal HUD 通过每个进程独立的匿名管道即时更新。
- 关闭管道或控制进程异常退出时，后台自动结束；引擎卡住时有有界退出兜底。

这是后台引擎交接，不等于 LSFG 本身已支持任意参数热更新。切换有预热时间和短暂双引擎资源开销；控制窗口不会重启。画质切换保持同一引擎进程。

## 性能、稳定性与画质修改

| 修改 | 实际作用与边界 |
| --- | --- |
| CPU 最新帧邮箱 + 最多 2 个 GPU 提交 | 限制 CPU/GPU 排队；忙时丢弃过期帧，避免用不断增加的队列掩盖处理不及时。不承诺在所有 GPU 上提高帧率。 |
| 尺寸配置去重、串行更新与合并 | 连续缩放时只处理最新的待更新尺寸，避免多个异步配置乱序覆盖。 |
| 共用采集配置构造 | 启动与尺寸变化时使用相同的格式、帧率和缓冲深度，减少配置漂移。 |
| 亮度诊断改为 `--diagnostics` 按需开启 | 日常模式不再每秒两次锁定/扫描采集 IOSurface；黑屏诊断仍可手动启用。 |
| 输出色彩空间缓存 | 不再每帧创建 sRGB 色彩空间对象。 |
| 锐化强度为零走直通 | 跳过 CAS shader 编译、两张中间纹理和额外处理。 |
| Lanczos 与自适应锐化恢复 UI | 原项目已有实现却被固定关闭；现在可以实时对比。Lanczos 只在需要重采样时执行，锐化纹理按尺寸复用。默认保留原始画质。 |
| 整屏模式过滤所有本工具进程 | 避免控制进程、旧引擎、新引擎的输出被再次采进来，防止反馈镜像。 |
| 整屏输出尺寸修正 | 以显示器尺寸输出，不再把整屏内容挤到所选源窗口的尺寸里。 |
| 签名恢复 | 优先复用已有私有证书；构建通过固定证书签名，减少重建造成的重复授权。私有证书不进入 Git。 |

画质仍为 SDR / 8-bit / sRGB。自适应锐化可以改善软细节，不能恢复不存在的信息，也不能消除 LSFG 在遮挡、快速运动和切镜头处的时域伪影。较高锐化强度可能放大噪点。没有直接套用 HDR/P3 格式，也没有未经对比替换插帧内核。

## 可重复验证

`zsh dev/verify-local.sh` 直接编译当前 `EngineSession.swift`，并提取当前实际 CASPass 代码运行 Metal 测试：

- 管道的分片/多消息解析、中文和转义字符往返、环境变量隔离。
- 正常退出、重复停止、忽略停止的进程在兜底时限内被清理。
- CAS 强度 0：平均像素误差 **0.000**，方向正确。
- 确定性软细节测试图、强度 0.5：平均梯度增益 **1.077**；纹理按尺寸复用。该数值仅代表此测试图，不是通用画质提升百分比。

`python3 dev/verify-live-settings.py` 使用实际 ScreenCaptureKit 动态测试窗口和 LSFG 二进制，保存事件到被 Git 忽略的 `dev/verification-live-settings/`；结束时恢复原偏好。

已验证：控制进程 PID 不变、真实生成帧增长、2×/3× 切换、性能模式、同一引擎实时画质、暂停停止渲染及恢复、连续修改最终值、窗口/整屏切换、杀死预热进程后保留原引擎、12× 扩展引擎与 2× 标准引擎互切、停止/重新开始/退出无残留。

没有宣称本轮全局 GPU 功耗降低多少、输入延迟降低多少，或已修复所有游戏的插帧伪影。多屏、HDR、DRM、特定游戏及长时间运行的兼容性需要各自独立测量。
